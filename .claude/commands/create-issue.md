# Step 1: 要件の明確化

ユーザーの要望をヒアリングし、Issueに必要な情報を収集します。

## タスク

### 1. まず自由に聞く

最初の質問は**自由記述**で「何をしたいですか？」と聞いてください。
選択肢で誘導せず、ユーザーが自分の言葉で説明できるようにします。

### 2. 調査して把握する

ユーザーの回答を受けたら、**まずコードベースを調査**して要望の内容を把握してください：

- 言及された機能・ファイル・コンポーネントを探索する
- 問題の原因や背景を理解しようとする
- 関連するコード、設定、ドキュメントを確認する

### 3. 言い換えて確認する

調査結果をもとに、ユーザーの要望を**自分の言葉で言い換えて**伝えてください：

- 「〜ということですね」と理解を示す
- 調査で分かったことを踏まえて具体化する

### 4. 不明点があれば質問する

言い換えた上で、まだ**わからないこと・曖昧なこと**があれば質問してください。

#### 質問方法

- **AskUserQuestionツールを使用**して質問する
- 判断が分かれる部分については**推奨度と理由**をつけて選択肢を提示する

#### 深掘りの観点

ユーザーの回答に応じて、課題が明確になるまで対話を続ける：

- **曖昧な表現があれば具体化を促す**
  - 「〇〇というのは具体的にどういう状況ですか？」
  - 「例えばどんなケースがありますか？」

- **背景が不明確なら経緯を聞く**
  - 「なぜこれが必要になりましたか？」
  - 「きっかけは何でしたか？」
  - 「どういう問題が起きていますか？」

- **ゴールが不明確なら完了条件を聞く**
  - 「何ができたら完了と言えますか？」
  - 「理想の状態はどうなっていますか？」

- **関連情報があるか確認する**
  - 「関連するSlackスレッドやドキュメントはありますか？」
  - 「関連するIssueやStoryはありますか？」

#### 完了の判断基準

以下の項目が明確になったら質問を終了し、次に進む：

- **概要**: 何をするのかが明確
- **背景**: なぜやるのかが明確
- **完了定義**: 何ができたら完了かが明確

**注意**: 調査と言い換えで既に上記が明確な場合は、質問せずに次に進んでください。

### 5. 確認

収集した情報をまとめて、ユーザーに確認してください。

#### テンプレート

```markdown
#### 概要

（何を実現したいかを1-2文で説明）

#### 背景・動機

（なぜこの機能/修正が必要なのかを説明）

#### 期待する動作

（具体的にどのように動作してほしいかを箇条書きで記載）

- 動作1
- 動作2

#### 受け入れ条件

（この Issue が完了したとみなす条件をチェックリスト形式で記載）

- [ ] 条件1
- [ ] 条件2

#### 補足情報

（参考資料、スクリーンショット、関連Issueなどがあれば記載）
```

#### 出力

1. Issueのタイトルを確定してください
2. 上記テンプレートに沿ったIssue本文を作成してください
3. 作成したタイトルと本文をユーザーに確認してください（AskUserQuestionを使用）

確認後、問題なければ次のステップに進みます。

### 6. 登録

前のステップで確定したタイトルと本文を使用して、`gh issue create` コマンドでIssueを作成してください。

#### コマンド形式

```bash
gh issue create --title "タイトル" --body "$(cat <<'EOF'
Issue本文をここに記載
EOF
)"
```

#### 実行手順

1. 上記コマンドを実行してIssueを作成
2. 作成されたIssueのURLをユーザーに報告

#### 出力

- 作成されたIssueのURL
- 完了メッセージ
